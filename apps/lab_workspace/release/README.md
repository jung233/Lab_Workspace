# Native release signing and packaging

The application version is `2.0.0+1`; the Android application id and Apple
bundle id are `org.labworkspace.app`. Do not distribute a release artifact until
the organization has supplied its signing identities and has validated each
native package on its supported operating systems.

## Android

Chaquopy's trusted Python runtime requires Android API 24 or newer, so
`android/app/build.gradle.kts` sets `minSdk = 24`. Local notifications require
compile SDK 35 or newer; the app pins compile SDK 36 and schedules inexact
alarms, avoiding exact-alarm special access. Android release signing reads
these environment variables and never uses the debug key:

* `LAB_WORKSPACE_UPLOAD_STORE_FILE`
* `LAB_WORKSPACE_UPLOAD_STORE_PASSWORD`
* `LAB_WORKSPACE_UPLOAD_KEY_ALIAS`
* `LAB_WORKSPACE_UPLOAD_KEY_PASSWORD`

Store the keystore outside source control and inject its passwords through the
release secret manager. If these values are absent, Gradle leaves the release
variant unsigned; that output is not distributable.

Calculation RPC is connected to Chaquopy plugin `com.chaquo.python` 17.1.0
with bundled CPython 3.15.0 and fixed `python/mobile` sources. API 23 devices are
not supported. The mobile bridge accepts typed JSON-RPC only; it does not
install packages or execute model-provided source at runtime.

## iOS

The deployment target is iOS 14.0. The Release configuration requires the
organization's Apple Developer Team and provisioning profile through:

* `LAB_WORKSPACE_APPLE_TEAM_ID`
* `LAB_WORKSPACE_APPLE_PROFILE_NAME`

Xcode must have the matching Apple Distribution identity and profile installed.
No certificate, team identifier, or provisioning profile is included in this
repository.

The Objective-C runner is part of the target and reports unsupported until the
official Python 3.15.0 iOS XCFramework is installed at
`ios/Python.xcframework`. Obtain `python-3.15.0-iOS-XCframework.tar.gz` from the
[official Python 3.15.0 release](https://www.python.org/downloads/release/python-3150/)
and verify SHA-256
`68e98ab35cc0643ba3a227a8c7768da45c2a5e67dbe1bc26598537e96680fd19` before
extracting. In Xcode, add `Python.xcframework` to Runner's Frameworks, Libraries
and Embedded Content, choose **Embed & Sign**, and expose its framework headers
to the Objective-C target. The checked-in Run Script phase bundles only the
fixed app-owned calculation modules; it skips runtime setup when the XCFramework
is absent, and native capability probing remains unsupported in that case.

## Windows

Windows toast notifications use the stable app id `org.labworkspace.app`. The
repository does not include an MSIX publisher identity or signing certificate.
Before shipping, the organization must assign its reserved package identity,
publisher distinguished name, version policy, and code-signing certificate,
then package and sign with the Windows SDK `MakeAppx` and `SignTool`. Never
commit a `.pfx` or certificate password. An unpackaged executable is not an
MSIX distribution and has reduced Windows notification management support.

## Validation still required

This source tree has not been built or signed on Windows, Android, or macOS.
The Windows Flutter plugin registrant is generated by Flutter after package
resolution; the current workstation cannot create the plugin symlink tree while
Windows Developer Mode is disabled. The dependency lockfile is resolved, but a
release owner must regenerate platform plugin metadata and perform native
release validation on configured build hosts.

The pinned Flutter toolchain is 3.47.7. From this directory, invoke
`../../tooling/release/build_android.ps1` on Windows for the signed Android
App Bundle, `../../tooling/release/build_windows.ps1` for the Windows release
executable, or `../../tooling/release/build_ios.sh` on macOS with an
organization-provided export options plist. These scripts check the Flutter
version and required signing environment before invoking release packaging;
they are not run as part of source analysis.
